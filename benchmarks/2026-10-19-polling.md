# Worker 轮询间隔调优记录（2026-10-19）

## 改动与对照条件

上次压测的 2 个 Worker 每个最多领取 20 条任务，轮询间隔为 1000 ms；在 40 条有序端点流下，45 事件/秒会逐步积压。本次仅将 Compose 的 `WORKER_POLL_INTERVAL_MS` 默认值调整为 250 ms，保持 2 个 Worker、批量上限 20、40 条端点流、独立 Node.js 接收端和本机 Docker Desktop 环境不变。每轮数据使用独立租户和事件类型。旧数据没有被改写。

| 配置 | 输入负载 | 接受 / 最终成功 | 发压结束时成功 / 待投递 | 投递 P95 | API P95 | 原始报告 |
| --- | --- | ---: | ---: | ---: | ---: | --- |
| 1000 ms | 45/s × 30s | 1350 / 1350 | 1174 / 176 | 4.191 s | 22.58 ms | `e73a12f5e611` |
| 250 ms | 45/s × 30s | 1350 / 1350 | 1350 / 0 | 0.243 s | 21.81 ms | `8956b99e6088` |
| 250 ms | 45/s × 30s | 1350 / 1350 | 1347 / 3 | 0.250 s | 21.68 ms | `fb6b69dba7dc` |

同日对照中，投递 P95 从 4.191 秒降到 0.243–0.250 秒；API P95 基本保持不变。三轮 250 ms 配置均在发压结束后不到 1 秒内完成全部投递。轮询更频繁会增加数据库空轮询，因此它是延迟与数据库开销之间的配置选择，不能仅凭本机结果推断其他部署环境的最优值。

## 十分钟持续负载

为检查持续运行时的积压与延迟，在相同的本机 Docker Desktop、2 个 Worker、250 ms 轮询、40 条端点流和快速 HTTP 200 接收端条件下，再以 15 events/s 连续发压 600 秒。此轮是一次 soak 观察，不是重复三轮的容量认证。

| 输入负载 | 接受 / 最终成功 | 发压结束时成功 / 待投递 | 最老待投递年龄 | API P50 / P95 / P99 | 投递 P50 / P95 / P99 | 原始报告 |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| 15/s × 600s | 9000 / 9000 | 8999 / 1 | 173 ms | 20.88 / 22.40 / 23.49 ms | 132.73 / 248.32 / 257.46 ms | `3670684844a8` |

最终 9000 个投递全部成功，0 个拒绝、死信或遗留待处理任务；发压结束后约 0.8 秒清空最后一条任务。该结果支持“在本机该配置下完成一次 10 分钟 15 events/s soak”，不代表生产容量，也没有覆盖故障比例、外部慢端点或目标生产规格。

所有轮次最终成功，均为每个事件恰好一次成功尝试，0 个死信。150 事件/秒在本机 60 秒观察窗口内没有持续增长的队列积压；200 事件/秒产生明显积压，结束后约 7.8 秒才全部清空。由领取批量、轮询间隔与端点顺序约束推断，40 条流在此配置下的并行领取能力接近每秒 160 次；200 事件/秒的结果与这个数量级吻合。这是对本测试条件的解释，不是严格的容量上限证明。

压测期间的一次 `docker stats --no-stream` 快照显示 PostgreSQL CPU 约 36.5%；结束后的一次快照约 2.3%。快照不能代表峰值或长期平均值。本次没有覆盖慢接收端、失败重试、网络抖动和更长运行时间，因此简历应写“本机 60 秒负载下承载 150 事件/秒”，不要写“生产级最大吞吐量 150 事件/秒”。

## 复现

本记录的结果来自 RabbitMQ/独立 Delivery Service 改造前的共享数据库架构，保留为历史数据。当前 Compose 的复测应启动 API、Delivery Service、两个数据库、RabbitMQ 与独立接收端，并使用 `docker compose up -d --scale delivery-service=2 delivery-service`。当前架构的结果应另存新报告，不能与此处旧数据混为同一组。

```powershell
node scripts/benchmark.mjs --rate=150 --duration-seconds=60 --concurrency=48 --streams=40 --timeout-seconds=240
```

原始 JSON 位于 `benchmarks/results/`，包含完整 API 延迟样本、数据库投递统计和实际 Worker 轮询配置。早期两份对照报告没有记录该环境变量，配置由本记录和当时的容器配置确认。

## 可用于简历的表述
